## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) scored a drawn 3×3 grid and reported `sample-sanity` recall@1 on it. This notebook keeps that grid and its inference contract as Section 5 and adds the adaptation contract around it: a real out-of-distribution captioning corpus read column-only with per-photograph pins from two parquet row groups, a retrieval protocol over a 391-photograph gallery in the carried `metrics.py` (recall@k both ways, median rank, rsum, ITM re-ranking, ITM pair accuracy), two non-neural baselines, a bounded fine-tuning with BLIP's ITC + ITM objectives and the vision features cached, a per-category breakdown, the grid re-scored after adaptation, and an artifact that reloads. The per-grid `evaluation_report` helper is unchanged; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 8-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9, MOD12):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `pytorch_model.bin`), at the pinned revision; `verify_snapshot` re-hashes every entry — the pickle checkpoint included — before `torch` is imported; `BlipItmPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`, `use_safetensors=False`, `weights_only=True`). **Executed ≠ hosted artifact:** the notebook runs `pytorch_model.bin` (the only PyTorch weight file upstream; no SafeTensors exists at this revision); the `tf_model.h5` DIMER hosts is never listed or fetched, and both digests are in the card. No cell outside the carried modules calls `huggingface_hub`, `transformers`, `pyarrow`, `safetensors`, `urllib` or the model's encoders directly.
- **Data (DAT1–DAT9, ST6):** the default sample's captions are the `id`, `answer`, `question_type` and `text_detected` columns of one object in the Hub dataset repository `mm-eval/VizWiz-Captions` at the immutable revision `c4a6d897836e7885d0095134f92d392e4e770539` (`data/val-00004-of-00005.parquet`, 392,245,504 bytes, SHA-256 `4492465a…`): the declared size and SHA-256 are checked against the pins through the Hub's file metadata before any byte is read, only the parquet footer and those columns are fetched over HTTPS range requests through `pyarrow` (about 0.5 MB), and the decoded columns are refused unless their SHA-256 matches the pin. The 672 photographs of row groups 0 and 1 are then read from the shard's image column the same way (one range read per row group, about 166 MB), each pinned by size and SHA-256 in the carried `samples.py` and refused on any mismatch; captions over the 256-character scoring ceiling are dropped (one of 1,391 in row group 0) and duplicates removed; the 318 captioned row-group-0 photographs are cut **by image** into 208 / 40 / 70 and row group 1's 321 captioned photographs are appended to the test split as the gallery (`check_split_disjoint` asserts no shared image id). The template adds a second *External access* bullet naming the repository, the revision, the file, the byte counts and the CC BY 4.0 licence.
- **Stages (§4.1):** `fetch_annotations` + `fetch_images` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + refusal probes (validation, with three digests) → `validate_inputs` + `pipe.score` with sanity checks + `evaluation_report` on the drawn grid (inference contract) → `chance_baseline` + `colour_keyword_baseline` + `pipe.evaluate` on the frozen model with the per-category breakdown (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.score` + `evaluation_report` on the grid again (inference) → `pipe.save_artifact` → `BlipItmPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** neither the ITM probability nor the ITC cosine is calibrated and neither abstains; recall@k, median rank and rsum are gallery-relative (own numpy implementation of the COCO retrieval protocol; a 70-photograph gallery saturates them, which is why the gallery is 391) and none is a human judgement; no acceptance threshold ships. The grid re-scored after adaptation carries a `sample-sanity` verdict that names the missing dispersion.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the chance and colour-keyword baselines and the frozen model are scored on the same 391-photograph gallery as the adapted model, on the six recalls, rsum, the ITM re-ranking and per category; every metric is labelled as one seeded split of one corpus with no dispersion estimate, and the notebook says explicitly that the frozen model is already a competent retriever, that the measured gain is a few recall points carried by the image → text direction, that the ITM pair accuracy did not move, and that the gallery size moves the numbers more than the adaptation does.
- **Split integrity (SPL1–SPL8):** the split is seeded and image-disjoint; validation (40 photographs, a saturated gallery) selects the epoch and the test split is used for nothing but the final evaluation; the notebook states that images from few photographers or sessions must be split by source.
- **Ceilings (VAL6):** `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `IMAGE_SIZE` (384), `MAX_IMAGES` (16), `MAX_TEXTS` (16), `MAX_TEXT_CHARS` (256), the record bounds (8..5,000), `MIN_CAPTIONS` (1), `MAX_CAPTION_CHARS` (256) and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one input refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, one zip is read member by member (names flattened, no `extractall`) into the runtime and its records flow through the same validation, image-disjoint split, baselines, fine-tuning, evaluation, export and reload cells. The expected schema and the privacy guidance — photographs of people, documents or homes are restricted data — are stated in the Prerequisites and in Section 4, and the training split is written to `outputs/blip_itm_train.jsonl` in the JSONL shape.
- Licence: the weights are BSD-3-Clause and the notebook, README, card and `docs/WEIGHTS.md` say so; the corpus is CC BY 4.0 and is not redistributed — the export records its repository, revision, file pin, gallery row group and licence under `corpus`.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.

## Shared Vision-Language Retrieval learning unit — 2026-09-26

`DIMER_MultiModel_Vision_Language_Retrieval_Workshop.ipynb` is one learning unit with BLIP ITM and SigLIP2 repository entry points. Both carry identical executable cells. It remains **Candidate**; earlier primary notebook evidence does not qualify this supplemental three-model comparison.

The optional BYOD ZIP now runs actual SigLIP2, SigLIP v1 and BLIP ITC retrieval, BLIP ITM reranking, digest-verified embedding index export/reload and JSON/CSV results in an isolated run directory. STANDARD needs at least two evaluation images. FULL requires explicit train/validation/test roles with at least two images each; it adapts only on train, selects with validation, freezes before test and compares live adapted validation embeddings to a fresh adapter reload. Limits:128 images total,1–5 distinct string captions/image,256 characters/caption,16–4096px sides and100 million decoded pixels. Every image must be declared; duplicate decoded pixels are rejected within/across roles. ZIP extraction is nondestructive and rejects traversal, symlinks and duplicate members.

Runtime bootstrap retains an already imported NumPy2.x version and falls back to2.1.3, reflecting observed Colab2.1.3 preloads; other model/runtime pins are unchanged. Any incompatible preloaded packages still request a recorded session restart. This policy is tested locally, not a new uninterrupted hosted-run claim. ITM probabilities require exact cardinality and finite0–1 range; index reload checks digests and complete rankings in both directions.

The optional activity compares candidate-oracle recall at K5 versus10 on saved validation scores only. It does not require model reloads or overwrite canonical settings. Infrastructure cells are collapsed.
