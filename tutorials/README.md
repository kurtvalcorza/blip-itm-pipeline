## Conformance notes

- **Standalone carrier (NOTEBOOK_SPEC 2.0 §4):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/blip_itm_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 8-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating revision, the module's SHA-256, and the generator version.
- **Parity (PAR1–PAR3):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD8, MOD12):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry — the pickle checkpoint included — before `torch` is imported; `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files with `local_files_only=True`, `trust_remote_code=False`, `use_safetensors=False` and `weights_only=True` through `BlipForImageTextRetrieval`/`BlipProcessor`. **Executed ≠ hosted artifact:** the notebook runs `pytorch_model.bin` (the only PyTorch weight file upstream; no SafeTensors exists at this revision); the `tf_model.h5` DIMER hosts is never listed or fetched, and both digests are in the card. The notebook's only external dependencies are the pinned PyPI distributions and the Hub at the model revision.
- **Role stages:** `validate_inputs` writes `outputs/blip_itm_input_manifest.json` with the schema (384×384 resize, the two scores), the ceilings, each input's observed mode and size, the checked captions, the pair count, the verdict, and one recorded rejection finding from the duplicate-caption probe; `evaluation_report` writes `outputs/blip_itm_evaluation_report.json` — `sample-sanity` with image-to-text and text-to-image `recall_at_1` for the ITM probability and the cosine plus the chance baselines on the synthetic grid; `not-measurable` on BYOD (with what labelled data would make the task measurable).
- The default sample is three deterministic cartoon scenes drawn in code with Pillow (no text rendering, so their digests are stable across Pillow builds) and three authored captions — the same grid the smoke run used; recall@1 against a correspondence you drew and wrote yourself is sanity evidence for the input contract, preprocessing, both heads and the ranking, not a retrieval metric. **The fruit scene's own caption scored only 0.278** in the smoke run while still ranking first; the notebook records it so the reader sees an uncalibrated score.
- Score semantics (UNC1–UNC4): the ITM probability is an uncalibrated per-pair classifier output and the cosine is a similarity comparable only within a row or column; neither abstains, and the notebook says so before the first score and again in the interpretation section, and states that blank images still receive rankings (ITM 0.04–0.07 in the smoke run). The caption set is the caller-owned request parameter (the BYOD form field; the synthetic path's three captions) and is passed explicitly on the `score` call. The notebook performs no validation of its own — images and captions are checked only by the pipeline's `validate_inputs`/`score` path.
- Ceilings `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `IMAGE_SIZE` (384), `MAX_IMAGES` (16), `MAX_TEXTS` (16) and `MAX_TEXT_CHARS` (256) are printed before the model runs.
- CPU is documented as adequate (card-measured 3.9 s load, 3.1 s for the nine pairs of the 3×3 grid; 0.6 s for one pair on a 4096×4096 blank image); the notebook states that cost is two passes per pair and scales as images × captions, and that GPU rankings need not match CPU rankings on close pairs.
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
