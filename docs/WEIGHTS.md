# Weight provenance and DIMER hosting

- Upstream: `Salesforce/blip-itm-base-coco`
- Immutable revision: `bed8ad38cb2d04a5a4bdf2d071b3c3c0a4aa724c` (the Hub's `main` resolved to this commit on 2026-09-14)
- **Two weight files upstream, no SafeTensors:** `pytorch_model.bin` (895,139,697 bytes, float32, a PyTorch pickle; SHA-256 `017fb3e7f4e125f13a8a4717f1402dbe0d0bb877474b4a203db13a4447b0227f`, LFS `oid` confirmed by local re-hash) and `tf_model.h5` (895,599,664 bytes, the TensorFlow port; SHA-256 `735c126984ca09ef7d7195730381de5ea24e5b5815810f8b0da9a7476c1728e3` from the Hub's LFS pointer, not downloaded or re-hashed here). There is no `model.safetensors` at this revision and no conversion PR on the Hub.
- **Executed artifact ≠ hosted artifact (MODEL_ASSET_SPEC ID10).** This package executes `pytorch_model.bin` — the only PyTorch weight file — after its manifest SHA-256 is checked, with `weights_only=True`. DIMER does not accept `.bin` uploads, so the profile's hosted blob is the upstream `tf_model.h5` (an accepted format) — a different file with the same architecture and, per upstream, the same trained parameters, which this repository neither loads nor verifies against the PyTorch file (no `from_tf` path; MarianMT precedent). Both digests are recorded above and in `MODEL_CARD.md`; MODEL_ASSET_SPEC §27 conversion to `safetensors` would make the two artifacts equal and was not chosen for this wave (decision 2026-09-13).
- Manifest: `weights/blip-itm-base-coco/dimer-base-manifest.json` (8 files: `README.md`, `config.json`, `preprocessor_config.json`, `pytorch_model.bin`, `special_tokens_map.json`, `tokenizer.json`, `tokenizer_config.json`, `vocab.txt`; 896,093,679 bytes total, per-file SHA-256). `tf_model.h5` is deliberately not listed.
- Upstream weight license: BSD-3-Clause (the checkpoint's `README.md` front matter and the Hub's licence tag; the upstream code repository `salesforce/BLIP` carries the same licence)
- DIMER hosting: BSD-3-Clause permits use, modification, distribution, and commercial use subject to preservation of the copyright notice and disclaimer and to not using the Salesforce name for endorsement. The Git repository does not vendor either weight file (`weights/**/*.bin` and `weights/**/*.h5` are git-ignored); DIMER may mirror the upstream `tf_model.h5` in its model store under the upstream license.
- Fresh clone: `stage_missing_files(allow_download=True)` fetches only the manifest-listed files absent on disk, at the pinned revision, into the snapshot directory; `verify_snapshot()` then checks every file before any load. `weights/**` is marked `-text` in `.gitattributes` so Windows `core.autocrlf` cannot rewrite the committed small files and break their digests.
- Loader trust boundary (pickle checkpoint): `verify_snapshot` re-hashes `pytorch_model.bin` against the manifest **before** `torch` or `transformers` is imported, so a modified pickle never reaches a deserialiser; then `BlipForImageTextRetrieval.from_pretrained(<verified dir>, use_safetensors=False, weights_only=True, trust_remote_code=False, local_files_only=True)` makes `transformers` call `torch.load(..., weights_only=True)`, whose restricted unpickler admits tensors, primitives and containers only. The card-pass smoke wrapped `torch.load` and observed exactly two calls, both on `pytorch_model.bin` with `weights_only=True`; the BERT tokenizer (`vocab.txt`, `tokenizer.json`) comes from the same snapshot; nothing model-related is fetched at construction or inference (the smoke run loaded and ran with `HF_HUB_OFFLINE=1`).
