#### Description

`Salesforce/blip-itm-base-coco` is the Transformers-format release of the BLIP *base* model fine-tuned for image-text retrieval on COCO, from "BLIP: Bootstrapping Language-Image Pre-training for Unified Vision-Language Understanding and Generation" (Li, Li, Xiong, Hoi, arXiv:2201.12086), converted by the Hugging Face team and pinned here to revision `bed8ad38cb2d04a5a4bdf2d071b3c3c0a4aa724c` (the Hub's `main` on 2026-09-14). The snapshot `config.json` declares `BlipForImageTextRetrieval`: a 12-layer ViT-B/16 image encoder at 384×384 (hidden size 768, 576 patches plus a class token), a 12-layer BERT-style text encoder (hidden size 768, vocabulary 30,524) that doubles as an image-grounded text encoder through cross-attention, a 256-dimensional projection for both modalities (the ITC head, scored by cosine similarity), and a two-way ITM classification head over the fused `[CLS]` representation — 223,744,258 parameters in the 895 MB float32 `pytorch_model.bin`. The model was pretrained on 129M image–text pairs (COCO, Visual Genome, Conceptual Captions 3M/12M, SBU and a LAION subset, bootstrapped with BLIP's captioning-and-filtering procedure) with the ITC and ITM objectives and fine-tuned on COCO Captions for retrieval. At inference the processor (`BlipImageProcessor`, `preprocessor_config.json`: resize to 384×384 without preserving aspect ratio, CLIP mean/std) encodes each image, the BERT tokenizer encodes each caption, and per pair the model returns the ITM logits (`use_itm_head=True`, the upstream README's `itm_scores`) and the ITC cosine (`use_itm_head=False`, the README's `cosine_score`); this package softmaxes the ITM logits into a match probability and ranks captions per image by it. The pipeline also carries a bounded adaptation contract: `adapt` fine-tunes the last *k* blocks of the fused text encoder plus `vision_proj`, `text_proj` and `itm_head` (two blocks by default, 19,298,818 parameters; the vision encoder and the text embeddings stay frozen) on a validated `{id, image, captions}` dataset with BLIP's image-text contrastive loss (in-batch, temperature 0.07) and image-text matching loss (in-batch hard negatives sampled by ITC similarity), the frozen vision features computed once, selecting the epoch by validation rsum; `evaluate` scores retrieval over a gallery of every record's captions; `save_artifact` / `from_artifact` export and reload exactly those tensors as safetensors with a manifest bound to this base revision and weight digest. The tutorial's default corpus is VizWiz-Captions (`mm-eval/VizWiz-Captions` on the Hub at `c4a6d897836e7885d0095134f92d392e4e770539`, CC BY 4.0): the four text columns of one pinned shard read column-only over HTTPS range requests and the 672 photographs of its first two row groups read the same way, each pinned by size and SHA-256. **Weight format:** upstream hosts no SafeTensors at this revision — only `pytorch_model.bin` (a pickle) and `tf_model.h5` (the TensorFlow port). This package executes the pickle after its manifest SHA-256 is checked, with `weights_only=True`; DIMER does not accept `.bin` uploads, so the profile's hosted blob is `tf_model.h5`, a different file this package never loads (both digests under §Immutable provenance). What this repository adds is packaging: `verify_snapshot` and `stage_missing_files` (manifest digest checking and fresh-clone staging), `BlipItmPipeline.from_pretrained` (verified local loading with `trust_remote_code=False`, `use_safetensors=False`, `weights_only=True`), `format_texts`, `score` (input validation, both scores for every pair, per-image rankings, backend output checks), `recall_at_1`, the `validate_inputs` and `evaluation_report` stage helpers, the retrieval protocol `gallery`, `retrieval_metrics`, `itm_pair_accuracy` with the `chance_baseline` and `colour_keyword_baseline` (numpy, in `metrics.py`), the dataset contract `validate_dataset`, `split_dataset`, `check_split_disjoint`, `load_byod_dataset`, `write_dataset_jsonl` and the pinned-corpus readers `fetch_annotations`, `fetch_images`, `build_sample_dataset`, `fetch_sample_dataset` (in `samples.py`), and the adaptation contract `evaluate`, `adapt`, `save_artifact`, `load_artifact`, `from_artifact`.

#### Intended Use and Limitations

The uses below are the ones the package was built to support; everything else is either out of scope (§Out-of-scope use cases) or prohibited (§Use cases).

###### Primary Intended Uses

The task is image-text matching over a small grid: input 1–16 images (`PIL.Image.Image`, any mode, converted to RGB) and 1–16 captions; output, per pair, the ITM match probability, the raw ITM match logit and the ITC cosine similarity, plus the captions ranked per image. Envisioned applications are re-ranking a shortlist of candidate captions or images produced by a cheaper index, checking whether an alt-text or product description fits its image, choosing the best of a few caller-written descriptions, and prototyping of retrieval systems — with the ranking checked by a person before it is stored or acted on. The second intended use is bounded supervised adaptation: given a small labelled sample of the deployment's own photographs with one or more matching captions each, `adapt` fine-tunes the text encoder's last blocks, the projections and the ITM head and `evaluate` reports recall@1/5/10 in both directions, median rank, rsum, ITM re-ranking and ITM pair accuracy over an image-disjoint gallery beside two non-neural baselines, so an operator can measure whether the base model's COCO alignment moves toward their corpus before deciding anything. Within DIMER the pipeline is an inference component, a zero-configuration baseline for image-text matching and a bounded adaptation contract, not a corpus-scale retrieval engine and not a certified verifier of descriptions.

###### Primary Intended Users

Intended users are machine-learning engineers, search and content developers, and researchers integrating image-text matching into research prototypes or in-house tooling, and adapting it to an image population for which they hold a small set of photographs with matching captions. A user is expected to understand that the ITM probability is an *uncalibrated per-pair classifier output* — 0.998 does not mean a 99.8 % chance of a correct description, and the fruit scene's own caption scored 0.28 in the smoke run — that the cosine is comparable only within a row or column of the grid, that neither score abstains (a caption set with nothing that fits still yields a best caption), that every pair is a full forward pass so the grid is capped at 16×16, that the model was fine-tuned on COCO photographs with human captions so drawings, documents, non-English captions and fine attribute distinctions are distribution shifts, that the forward pass is deterministic on a fixed device but GPU and CPU scores can differ slightly, and that retrieval quality can only be measured on captioned images they supply. A user of `adapt` is expected to understand that recall@k is gallery-relative (the same frozen model scores rsum 5.72 on 70 photographs and 5.02 on 391), that the frozen model is already a competent retriever so a few hundred photographs move recall by a few points, that one seeded split gives no dispersion estimate, and that an adapter is a derived work of the weights and of the captions it trained on. Users who need captioning, question answering, corpus-scale search or precomputed embeddings are expected to know none of that is provided here.

###### Out-of-scope use cases

1. **Capability boundary:** no captioning or question answering (separate checkpoints), no corpus index or embedding export (every pair is scored on demand; recall@5/@10 and median rank need candidate sets this grid cannot express), no calibrated confidence, no abstention, no localisation of what matched, and no batching beyond the 16×16 grid in `score` (`evaluate` embeds a gallery in the kernel for the tutorial's protocol; it is not an index). Not a general training framework: `adapt` fine-tunes only whole blocks of the text encoder plus the two projections and the ITM head (1..12 blocks, no LoRA, no vision-encoder or embedding training, no scheduler, epochs capped at 20, learning rate at 1e-3, batch at 64, negatives only from the batch), selects an epoch on validation rsum, and writes one artifact format.
2. **Input boundary:** `score` rejects non-PIL images (`TypeError`), sides below `MIN_IMAGE_SIDE = 16` px or above `MAX_IMAGE_SIDE = 4096` px, more than `MAX_IMAGES = 16` images, a single string instead of a caption list, empty, non-string, over-long (`MAX_TEXT_CHARS = 256`) or duplicate-after-whitespace-collapse captions, and more than `MAX_TEXTS = 16` of them (`ValueError`/`TypeError`). Every image is resized to 384×384 without preserving aspect ratio, so thin panoramas are squashed and small details are lost; captions longer than the BERT tokenizer's positions are truncated. Datasets for `validate_dataset`, `evaluate` and `adapt` are lists of `{id, image, captions}` records: fewer than `MIN_RECORDS = 8` or more than `MAX_RECORDS = 5000` records, a duplicate or malformed id, an image that does not exist or does not decode, an empty caption list, a duplicated caption or one over `MAX_CAPTION_CHARS = 256` are refused with `ValueError` before any model import; `split_dataset` refuses fractions that leave fewer than 8 training records; `load_artifact` refuses an adapter whose format, version, base id, revision, weight file or digest differ, whose weight path escapes the artifact directory, or whose tensor set differs from the recorded configuration.
3. **Input boundary:** the fine-tuning data is COCO Captions — everyday photographs with five crowd-written captions each. Drawings (the tutorial's scenes), screenshots, documents, charts, medical or aerial imagery, captions in languages other than English, and captions that hinge on attributes the model treats loosely (colour, count, position — `a blue house` 0.005 but `a house` 0.30 against a red house in the smoke run) fall outside what the upstream authors evaluated and what this repository measured; results on them are undefined, not merely degraded. An image with no content still receives a ranking (see §Risks and harms). The adaptation sample is VizWiz-Captions — photographs by blind users, often blurry or badly framed, captions that name what is held and what a label says — and the recorded gain is specific to that population and caption style.
4. **Decision boundary:** not for autonomous decisions that act on a match score — publishing or rejecting alt-text, moderation or authenticity judgements about whether a caption "truly" describes an image, deduplication or licensing decisions, identity or provenance claims — without a human comparing the pair, and a locally measured recall@k on the deployment's own captioned images over a gallery of the deployment's own size. A gain on the operator's validation split is not a release decision: it is a single seeded split of one corpus with no dispersion estimate, and a saturated validation gallery selects the epoch weakly.

#### Factors

###### Groups

This pipeline is human-centric whenever a caption names a person or a personal attribute: `a woman cooking`, `an old man`, `a child with a disability`, or captions naming skin, dress, religion or nationality make the model score people against those descriptions, and both the CLIP-style contrastive head and the fused ITM head are documented in the vision–language literature to encode social biases in how such phrases match images. Neither the upstream authors nor this repository audited match scores by the depicted person's gender, age, skin tone, disability, dress or setting, and the tutorial contains no people at all. Non-human groups whose accuracy is unknown, not known to be equal: non-photographic images (the tutorial's cartoons, where the fruit scene matched its own caption weakly), non-Western scenes, food, clothing and objects, low-light or low-resolution captures, and captions in languages other than English or in non-native phrasing. An operator whose images or captions involve people is responsible for a fairness audit on their own pairs, stratified by depicted group and caption type, before relying on the output — and for deciding which captions about people are permitted at all (see §Use cases).

###### Instrumentation

The upstream "instrument" is web image–text pairs at whatever resolution and quality the source sites served, filtered by BLIP's own captioner/filter, and the fine-tuning instrument is COCO photography (consumer cameras, Flickr uploads) with crowd-written captions. Inference images arrive from whatever produced them — a phone camera, a screenshot, a render, a scanner — and resolution, exposure, colour balance, compression and aspect ratio all change the visual evidence; the fixed 384×384 resize discards aspect ratio and detail regardless of the source. Captions arrive from whatever wrote them — a person, a template, another model — and phrasing, length and specificity change the score as much as the image does. The pipeline validates type, size and caption shape only; it cannot detect a non-photographic image, a machine-generated caption, or a caption set that fits nothing. The synthetic tutorial scenes (flat Pillow shapes, no texture, no lighting) are themselves a rendering instrument unlike any COCO photograph, which is why the smoke run's weak fruit diagonal is recorded rather than tuned away.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0`, `torchvision==0.29.0`, `torchaudio==2.11.0`, `transformers==4.57.6`, `safetensors==0.8.0` (used only for the adapter artifact; the base checkpoint is a pickle), `numpy==2.5.3`, `pillow==11.3.0`, `huggingface-hub==0.36.2`, `pyarrow==25.0.1`, float32 on CPU; CUDA is used automatically when visible (float32). Inference, measured on the reference machine with the GPU hidden (`CUDA_VISIBLE_DEVICES=-1`) and the Hub offline (`HF_HUB_OFFLINE=1`): `verify_snapshot` on the 8-file, 895 MB snapshot 0.44 s; load 3.87 s with exactly two `torch.load(weights_only=True)` calls observed; the 3×3 grid (nine pairs, each an ITM and an ITC pass) 3.06 s; one pair on a 4096×4096 blank image 0.60 s — cost is two forward passes per pair, roughly independent of the input resolution after the resize, so a grid scales as images × captions. Retrieval and adaptation, measured on the RTX 5070 Ti (WSL, `cuda:0`, float32) in the build record: `evaluate` over the 391-photograph / 1,737-caption gallery with top-5 ITM re-ranking about 46 s (the gallery's images embedded once, every caption encoded once, 391 × 5 + 391 × 5 + 782 fused passes for the re-ranking and the pair accuracy); the 208 training photographs' vision features computed once, each epoch of 888 pairs at batch 16 (three fused passes per pair for the matching loss) plus the 40-photograph validation scoring about 25 s, the four-epoch default recipe 97 s; the CPU pre-flight of the same recipe is recorded in `docs/release-verification.md`. Data environment: the model assumes everyday photographs and COCO-style English captions; the synthetic tutorial scenes violate the first assumption on purpose (flat cartoons), which is where the weak fruit diagonal comes from. Documents, non-English captions, attribute-level distinctions and caption sets that fit nothing violate it to degrees this repository did not measure, and the pipeline reports no signal when they do.

#### Metrics

###### Performance Measures

Retrieval measures, named exactly as the code names them and implemented in numpy in `metrics.py` after the COCO retrieval protocol: over a gallery of every caption of every record, `i2t_recall_at_k` (k = 1, 5, 10; a photograph counts as a hit when any of its own captions is in the top k of the ITC cosine ranking), `t2i_recall_at_k` (each caption against the photographs), `i2t_median_rank` / `t2i_median_rank`, and `rsum` (the six recalls summed, 0..6); with `rerank_top_k` > 0, `itm_i2t_recall_at_1` and `itm_t2i_recall_at_1` re-rank the top candidates of every photograph and of every photograph's query caption with the ITM head, and `itm_pair_accuracy` scores each photograph's query caption against the hardest wrong caption by ITC (chance 0.5). `evaluate` runs them over a validated dataset with the verdict `measured` (at least `MIN_SCORED_RECORDS = 50` records) or `measured-small-sample`, and reports `by_category` sub-galleries. Two non-neural baselines frame every number: `chance_baseline` (the analytical expectation of a random ranking over the same gallery) and `colour_keyword_baseline` (bag-of-words F1 to the training captions plus a 3×3 mean-colour grid). The build record on the VizWiz sample (391-photograph gallery, RTX 5070 Ti): chance rsum 0.08, colour-keyword 0.13, frozen model rsum 5.023 (i2t R@1 0.742, t2i R@1 0.651, ITM-reranked i2t 0.803 / t2i 0.708, pair accuracy 0.683), adapted 5.158 (i2t R@1 0.790, t2i R@1 0.672, ITM-reranked i2t 0.841 / t2i 0.701, pair accuracy 0.683) — a few recall points carried by the image → text direction, one seeded split, no dispersion; on a 70-photograph gallery the same frozen model scores rsum 5.721 and nothing is left to gain. The ITM probability itself is an uncalibrated per-pair classifier output, the cosine is a similarity, and neither is a correctness signal. The repository also ships the retrieval field's simplest building block because it is what a caller would use to evaluate: `recall_at_1(scores, correct)` — the fraction of rows whose highest-scoring column is the labelled one — applied to both grids in both directions by the public `evaluation_report(result, correct_text_per_image=None)` stage, which returns image-to-text and text-to-image `recall_at_1` for the ITM probability and the cosine (the text-to-image direction only for a square one-to-one grid), the chance baselines (1/captions and 1/images) and the verdict `sample-sanity`, or the verdict `not-measurable` naming the labelled set that would be required when no correspondence is supplied. Retrieval is conventionally reported as recall@1/5/10 and median rank over thousands of candidates (COCO 5k, Flickr30k 1k), which this package's 16×16 grid cannot express; a deployment that needs those numbers must build its own candidate index and evaluation. The upstream paper's COCO retrieval recall@1 for its ViT-B models (upstream-reported; not restated here because the hosted card gives no number) is not reproduced or claimed by this pipeline.

###### Decision thresholds

No score threshold exists in the model: it scores every pair and the ranking picks the highest, nothing is filtered or abstained, and this package ships no cut-off on the ITM probability or the cosine — the smoke run's own captions scored 0.998, 0.634 and 0.278, so any fixed threshold would have accepted one drawn scene and rejected another. The decision parameter is the **caption set** (and the image set): which candidates are offered, how they are phrased, and whether the true match is among them — the same house scored `a red house` 0.64, `a house` 0.30, `a green tree` 0.02 and `a blue house` 0.005, so phrasing is part of the request. `format_texts` applies one fixed normalisation (whitespace collapsed; case preserved for the cased-insensitive BERT tokenizer to lower) so the same caption always produces the same score. A deployment owns its candidate sets and any threshold it applies, and decides how a match is verified before it is used.

###### Approaches to uncertainty and variability

Every reported corpus metric is one value on one seeded split of one corpus: the 672 photographs are the first two row groups of the pinned shard (not a random draw), `build_sample_dataset(seed=42)` fixes the assignment of row group 0's 318 captioned photographs into 208 / 40 / 70 and appends row group 1's 321 to the test gallery, `adapt(seed=0)` fixes the shuffle order and the hard-negative sampling, and no repetition over seeds or splits is performed, so no confidence interval or standard deviation is available and none is claimed — the gain on the gallery is a point estimate whose spread is unknown, the validation gallery that picks the epoch holds 40 photographs and saturates (rsum 5.82 → 5.89), and the build record's own sweep shows what moves the numbers: the gallery size (rsum 5.72 on 70 photographs, 5.02 on 391 for the same frozen model) far more than the recipe (two blocks at 2e-5 for four epochs 5.158; four blocks at 5e-5 for six epochs 5.157 on the small gallery, 5.757 versus 5.721 frozen). Inference run-to-run variability comes only from floating-point kernel selection across CPU builds and accelerators; there is no sampling and no seed to set, so a fixed input on fixed hardware is repeatable, but CPU and CUDA scores can differ in the low decimals and a close pair can swap ranks; the drawn scenes use no text rendering, so their bytes do not depend on the Pillow build. On the drawn 3×3 grid every image's own caption ranked first by both scores — ITM 0.998 (house), 0.634 (beach), 0.278 (fruit) with off-diagonal ITM ≤ 0.001, and cosine 0.495 / 0.422 / 0.441 on the diagonal against 0.199–0.292 off it — `recall_at_1` 1.0 in both directions by both scores, one observation on nine drawn pairs, not an estimate; a blank white image scored ITM 0.04–0.07 and cosine 0.29–0.33 against all three captions, and uniform noise ITM 0.001 and cosine 0.12–0.21, which is what a scorer with no abstention looks like — every pair receives a number and every image a best caption. A caller who needs a retrieval estimate must supply captioned images and compute recall@k over many candidates or bootstrap resamples themselves; a caller who needs a calibrated match probability has none from this model.

#### Ethical considerations and biases

No external ethics board, red-team, or population-specific clearance reviewed this repository or, to our knowledge, the upstream checkpoint; nothing below should be read as implying one.

###### Data

The upstream paper describes pretraining on 129M image–text pairs from COCO, Visual Genome, Conceptual Captions 3M and 12M, SBU Captions and a 115M-image LAION subset — web-scraped pairs whose images and captions can include real, identifiable people, copyrighted photographs and stereotyped or offensive text, filtered only by BLIP's own learned filter — and fine-tuning on COCO Captions, whose images are Flickr photographs of people and everyday scenes with crowd-written descriptions; personal data in the training corpora is therefore present by construction. Neither was audited here. The tutorial's adaptation corpus is VizWiz-Captions (Gurari et al., ECCV 2020; CC BY 4.0), photographs taken by blind people of their own surroundings — homes, documents, medication, food, people — with crowd-written captions; the VizWiz authors describe removing images with private content, but the photographs still show personal spaces and belongings, and the captions transcribe labels and screens. This repository reads the captions of one pinned shard column-only and 672 photographs from two row groups at run time and does not redistribute either. This repository distributes code, tests, and documentation; it does not distribute the 895,139,697-byte `pytorch_model.bin` (staged locally under `weights/blip-itm-base-coco/` and git-ignored) nor the 895,599,664-byte `tf_model.h5` (never fetched by this package), and it ships no sample photographs — the tutorial scenes are drawn in code and the VizWiz photographs are fetched and digest-verified at run time into a git-ignored cache. An adapter written by `save_artifact` carries no training images, but its tensors were shaped by the photograph–caption pairs, and the operator is responsible for the rights attached to those. The operator must audit the images and captions they submit for personal, proprietary, or otherwise restricted content; the pipeline performs no such check and will score a caption about a person's appearance as readily as one about a house.

###### Human Life

This pipeline is not intended for decisions in health, safety, criminal justice, employment, credit, or housing, and it has not been validated or certified for any of them by this repository, the upstream authors, or any regulator. Its only validation is the offline unit suite (40 tests, plus 6 model-backed tests that run when the snapshot is staged, one of them on CUDA) and the CPU and GPU runs recorded in this repository on one drawn grid and one VizWiz sample (the adaptation moved image → text recall over a 391-photograph gallery by about five points and left the ITM pair accuracy where it was). Foreseeable but unintended sensitive uses — accepting or rejecting alt-text for blind or low-vision users on the strength of a match score, deciding that an image "matches" a description of a person for identification or verification, moderation or authenticity judgements, screening user-submitted image–text pairs — would be admissible only with human review of every pair (the model scores any pair and gives no signal when the caption set fits nothing), a locally measured recall@k on the deployment's own captioned images stratified by depicted group, a documented candidate-set and threshold policy, an explicit list of captions about people that are refused before they reach the model, and whatever regulatory clearance the domain requires.

###### Mitigations

- **Supply-chain integrity:** `MODEL_REVISION` is a 40-hex commit; `stage_missing_files` refuses a manifest whose `modelId`/`revision` differ from the package constants and fetches only manifest-listed files at that revision when `allow_download=True`; `verify_snapshot` then checks all 8 listed files' byte sizes and SHA-256 before any load — **including the pickle checkpoint, so a modified `pytorch_model.bin` never reaches a deserialiser**; `from_pretrained` loads only from the verified directory with `local_files_only=True`, always passes `trust_remote_code=False`, `use_safetensors=False` (naming the format) and `weights_only=True` (restricted unpickler: tensors, primitives and containers only), and the smoke run loaded and scored with `HF_HUB_OFFLINE=1` while observing exactly two `torch.load(weights_only=True)` calls. The upstream `tf_model.h5` is neither listed nor loaded. A test flips one hex digit of a manifest digest and asserts the loader refuses; another asserts a foreign manifest is refused; the import-boundary tests assert that a missing or tampered snapshot is refused before `torch` or `transformers` is imported; another asserts the manifest lists the pickle and not the TensorFlow file.
- **Input integrity:** the public `validate_inputs(images, texts)` stage applies exactly the checks `score` applies (both route through one shared private checker) and returns an input manifest recording the schema, the ceilings, each input's observed mode and size, the checked captions, the pair count and the verdict; non-PIL inputs, sides outside 16–4096 px, too many images, and non-list, empty, non-string, over-long, duplicate or too many captions are rejected; `score` raises on a malformed runner result (missing keys, wrong ITM logit shape, non-finite values); `evaluation_report` rejects mismatched or invalid correspondences; `recall_at_1` rejects non-grid inputs.
- **Reproducibility:** exact `==` pins in `pyproject.toml`; deterministic forward passes and softmax; fixed caption normalisation; every result carries `model_id`, `model_revision`, the checked captions, the image sizes, the device and the dtype.
- **Refusals:** no corpus index, no batching beyond the grid, no download without the explicit flag, no Hub access at inference time, no unrestricted pickle deserialisation, no threshold invented, and no filtering of caption content — that policy is the operator's to implement around the pipeline.
- **Adaptation integrity:** `adapt` validates the dataset before any tensor is built, trains only the named tensors with every other parameter's `requires_grad` false, never samples a hard negative from the same photograph, restores the initial tensors and re-freezes the model if anything raises (including the caller's progress callback), and keeps the epoch with the best validation rsum rather than the last; `save_artifact` records the base id, revision, weight digest, tensor names, file size and SHA-256; `load_artifact` verifies format, version, base, path containment, digest and the exact tensor set before `safetensors` deserialises anything and refuses any tensor outside the text-encoder blocks, the projections and the ITM head. Split leakage is prevented by construction (`split_dataset` keeps every record on an image in one split; `check_split_disjoint` asserts it); baselines are computed on the same gallery as the model.
- No statistical mitigation (class balancing, subsampling) applies: the adaptation samples pairs uniformly, the negatives come from the batch, and the reported metrics are unweighted; a corpus of unrelated photographs gives the ITM head only easy negatives.

###### Risks and harms

- **A best caption for anything:** the model has no abstention — a blank image and uniform noise both received rankings in the smoke run — so a caption set with nothing that fits still crowns a caption, and a consumer that trusts `rankings[0]` (alt-text pickers, deduplication, moderation) inherits the error silently.
- **Uncalibrated match probabilities:** 0.278 was the correct match for the fruit scene and 0.634 for the beach; a fixed threshold accepts and rejects arbitrarily across images, and a high probability is not evidence of a correct description.
- **Phrasing dependence:** the score follows the caption's wording (`a red house` 0.64 vs `a house` 0.30 for the same image); a deployment that authors candidates carelessly authors the ranking.
- **Scoring people by description:** captions naming appearance, dress, ethnicity or disability are scored against images of people with the documented biases of vision–language models; such use can cause direct harm and is prohibited below.
- **Automation bias:** a probability that reads like a confidence invites trust that a per-pair classifier has not earned.
- **Pickle checkpoint:** the executed weight file is a pickle; the digest check and `weights_only=True` are the mitigation, and a caller who bypasses `from_pretrained` and loads the file another way forfeits both.
- **Bias amplification:** any image population or caption style COCO under-represents (non-Western scenes, non-photographic images, minority groups, non-native phrasing) is reproduced as uneven match quality, undetected because no per-group evaluation exists.
- **Alignment capture, not truth:** an adapter trained on captions that transcribe labels learns to align the words on a label with its photograph, and scores a caption naming a label the image does not show as readily as one it does — recall rewards the corpus's pairing, not its truth.
- **Gallery inflation:** recall@k on a small gallery is near the ceiling for any competent retriever (rsum 5.72 of 6 on 70 photographs in the build record); a deployment that reports recall on a shortlist is reporting the shortlist.
- **Resource use:** an 895 MB model and ~0.35 s per pair on the reference CPU; a 16×16 grid is 256 pairs. Adaptation holds the vision features of every training photograph in memory (577×768 floats each) and the optimiser state of 19.3 M parameters; the default recipe takes about 100 s on the RTX 5070 Ti and 561 s on the reference CPU, and `evaluate` with top-5 ITM re-ranking over the 391-photograph gallery about 46 s on the GPU and 236 s on the CPU.

###### Use cases

Prohibited even where the model would work: scoring images of people against captions that name or infer protected characteristics (race, ethnicity, religion, health, disability, sexual orientation), or to identify, verify, track, profile or surveil individuals; processing images or captions the operator has no right to process, including intimate imagery and licence-restricted material; fine-tuning on photographs or captions whose subjects or authors have not consented to that processing where consent is required; presenting match scores as verified descriptions, authenticity judgements or evidence without human review; and any use that violates the upstream BSD-3-Clause licence terms (including use of the Salesforce name for endorsement), the DIMER deployment terms, or the consent and data-protection obligations attached to the images and captions processed. Autonomous high-consequence actions triggered by unreviewed match scores are prohibited by the intended-use contract above.

## Input/output contract

- `BlipItmPipeline.from_pretrained(device=None, weights_dir=None, allow_download=False)` — stages missing manifest files (only with `allow_download=True`), verifies digests, loads; `device` defaults to `cuda:0` when visible, else `cpu`; float32 on both.
- `score(images, texts) -> dict` with keys `itm_probability`, `itm_logit_match`, `cosine` (float64 grids indexed `[image][text]`), `rankings` (per image: `text`, `itm_probability`, `cosine`, descending by ITM probability), `texts` (checked), `n_images`, `image_sizes`, `device`, `dtype`, `source`, `model_id`, `model_revision`.
- `format_texts(texts) -> list[str]`; `recall_at_1(scores, correct) -> float`.
- Ceilings and constants: `MIN_IMAGE_SIDE = 16`, `MAX_IMAGE_SIDE = 4096`, `MAX_IMAGES = 16`, `MAX_TEXTS = 16`, `MAX_TEXT_CHARS = 256`, `IMAGE_SIZE = 384`, `WEIGHT_FILE = "pytorch_model.bin"`, `HOSTED_TF_WEIGHT_FILE = "tf_model.h5"`, `INPUT_SCHEMA`.
- `evaluate(records, *, rerank_top_k=0) -> dict` — embeds every validated record's photograph and every caption once, returns `retrieval_metrics` over the ITC cosine grid, `by_category` sub-galleries, and with `rerank_top_k` in 1..50 the ITM re-ranked recall@1 in both directions (text → image over each record's query caption) and the ITM pair accuracy, plus `verdict`, `adapted`, `seconds`; `adapt(train, val=None, *, epochs=4, lr=2e-5, batch_size=16, trainable_text_layers=2, seed=0, progress=None) -> dict` — bounded fine-tuning with the ITC + ITM objectives and validation-rsum epoch selection, transactional on failure; `save_artifact(output_dir, metadata=None) -> Path`; `load_artifact(artifact_dir) -> dict`; `from_artifact(artifact_dir, *, device=None, weights_dir=None, allow_download=False)`.
