#### Description

`Salesforce/blip-itm-base-coco` is the Transformers-format release of the BLIP *base* model fine-tuned for image-text retrieval on COCO, from "BLIP: Bootstrapping Language-Image Pre-training for Unified Vision-Language Understanding and Generation" (Li, Li, Xiong, Hoi, arXiv:2201.12086), converted by the Hugging Face team and pinned here to revision `bed8ad38cb2d04a5a4bdf2d071b3c3c0a4aa724c` (the Hub's `main` on 2026-09-14). The snapshot `config.json` declares `BlipForImageTextRetrieval`: a 12-layer ViT-B/16 image encoder at 384×384 (hidden size 768, 576 patches plus a class token), a 12-layer BERT-style text encoder (hidden size 768, vocabulary 30,524) that doubles as an image-grounded text encoder through cross-attention, a 256-dimensional projection for both modalities (the ITC head, scored by cosine similarity), and a two-way ITM classification head over the fused `[CLS]` representation — about 224M parameters in the 895 MB float32 `pytorch_model.bin`. The model was pretrained on 129M image–text pairs (COCO, Visual Genome, Conceptual Captions 3M/12M, SBU and a LAION subset, bootstrapped with BLIP's captioning-and-filtering procedure) with the ITC and ITM objectives and fine-tuned on COCO Captions for retrieval. At inference the processor (`BlipImageProcessor`, `preprocessor_config.json`: resize to 384×384 without preserving aspect ratio, CLIP mean/std) encodes each image, the BERT tokenizer encodes each caption, and per pair the model returns the ITM logits (`use_itm_head=True`, the upstream README's `itm_scores`) and the ITC cosine (`use_itm_head=False`, the README's `cosine_score`); this package softmaxes the ITM logits into a match probability and ranks captions per image by it. Nothing is trained or adapted here. **Weight format:** upstream hosts no SafeTensors at this revision — only `pytorch_model.bin` (a pickle) and `tf_model.h5` (the TensorFlow port). This package executes the pickle after its manifest SHA-256 is checked, with `weights_only=True`; DIMER does not accept `.bin` uploads, so the profile's hosted blob is `tf_model.h5`, a different file this package never loads (both digests under §Immutable provenance). What this repository adds is packaging: `verify_snapshot` and `stage_missing_files` (manifest digest checking and fresh-clone staging), `BlipItmPipeline.from_pretrained` (verified local loading with `trust_remote_code=False`, `use_safetensors=False`, `weights_only=True`), `format_texts`, `score` (input validation, both scores for every pair, per-image rankings, backend output checks), `recall_at_1`, and the `validate_inputs` and `evaluation_report` stage helpers.

#### Intended Use and Limitations

The uses below are the ones the package was built to support; everything else is either out of scope (§Out-of-scope use cases) or prohibited (§Use cases).

###### Primary Intended Uses

The task is image-text matching over a small grid: input 1–16 images (`PIL.Image.Image`, any mode, converted to RGB) and 1–16 captions; output, per pair, the ITM match probability, the raw ITM match logit and the ITC cosine similarity, plus the captions ranked per image. Envisioned applications are re-ranking a shortlist of candidate captions or images produced by a cheaper index, checking whether an alt-text or product description fits its image, choosing the best of a few caller-written descriptions, and prototyping of retrieval systems — with the ranking checked by a person before it is stored or acted on. Within DIMER the pipeline is an inference component and a zero-configuration baseline for image-text matching, not a corpus-scale retrieval engine and not a certified verifier of descriptions.

###### Primary Intended Users

Intended users are machine-learning engineers, search and content developers, and researchers integrating image-text matching into research prototypes, internal tooling, or the DIMER workbench. A user is expected to understand that the ITM probability is an *uncalibrated per-pair classifier output* — 0.998 does not mean a 99.8 % chance of a correct description, and the fruit scene's own caption scored 0.28 in the smoke run — that the cosine is comparable only within a row or column of the grid, that neither score abstains (a caption set with nothing that fits still yields a best caption), that every pair is a full forward pass so the grid is capped at 16×16, that the model was fine-tuned on COCO photographs with human captions so drawings, documents, non-English captions and fine attribute distinctions are distribution shifts, that the forward pass is deterministic on a fixed device but GPU and CPU scores can differ slightly, and that retrieval quality can only be measured on captioned images they supply. Users who need captioning, question answering, corpus-scale search or precomputed embeddings are expected to know none of that is provided here.

###### Out-of-scope use cases

1. **Capability boundary:** no captioning or question answering (separate checkpoints), no corpus index or embedding export (every pair is scored on demand; recall@5/@10 and median rank need candidate sets this grid cannot express), no calibrated confidence, no abstention, no localisation of what matched, and no batching beyond the 16×16 grid.
2. **Input boundary:** `score` rejects non-PIL images (`TypeError`), sides below `MIN_IMAGE_SIDE = 16` px or above `MAX_IMAGE_SIDE = 4096` px, more than `MAX_IMAGES = 16` images, a single string instead of a caption list, empty, non-string, over-long (`MAX_TEXT_CHARS = 256`) or duplicate-after-whitespace-collapse captions, and more than `MAX_TEXTS = 16` of them (`ValueError`/`TypeError`). Every image is resized to 384×384 without preserving aspect ratio, so thin panoramas are squashed and small details are lost; captions longer than the BERT tokenizer's positions are truncated.
3. **Input boundary:** the fine-tuning data is COCO Captions — everyday photographs with five crowd-written captions each. Drawings (the tutorial's scenes), screenshots, documents, charts, medical or aerial imagery, captions in languages other than English, and captions that hinge on attributes the model treats loosely (colour, count, position — `a blue house` 0.005 but `a house` 0.30 against a red house in the smoke run) fall outside what the upstream authors evaluated and what this repository measured; results on them are undefined, not merely degraded. An image with no content still receives a ranking (see §Risks and harms).
4. **Decision boundary:** not for autonomous decisions that act on a match score — publishing or rejecting alt-text, moderation or authenticity judgements about whether a caption "truly" describes an image, deduplication or licensing decisions, identity or provenance claims — without a human comparing the pair, and a locally measured recall@k on the deployment's own captioned images.

#### Factors

###### Groups

This pipeline is human-centric whenever a caption names a person or a personal attribute: `a woman cooking`, `an old man`, `a child with a disability`, or captions naming skin, dress, religion or nationality make the model score people against those descriptions, and both the CLIP-style contrastive head and the fused ITM head are documented in the vision–language literature to encode social biases in how such phrases match images. Neither the upstream authors nor this repository audited match scores by the depicted person's gender, age, skin tone, disability, dress or setting, and the tutorial contains no people at all. Non-human groups whose accuracy is unknown, not known to be equal: non-photographic images (the tutorial's cartoons, where the fruit scene matched its own caption weakly), non-Western scenes, food, clothing and objects, low-light or low-resolution captures, and captions in languages other than English or in non-native phrasing. An operator whose images or captions involve people is responsible for a fairness audit on their own pairs, stratified by depicted group and caption type, before relying on the output — and for deciding which captions about people are permitted at all (see §Use cases).

###### Instrumentation

The upstream "instrument" is web image–text pairs at whatever resolution and quality the source sites served, filtered by BLIP's own captioner/filter, and the fine-tuning instrument is COCO photography (consumer cameras, Flickr uploads) with crowd-written captions. Inference images arrive from whatever produced them — a phone camera, a screenshot, a render, a scanner — and resolution, exposure, colour balance, compression and aspect ratio all change the visual evidence; the fixed 384×384 resize discards aspect ratio and detail regardless of the source. Captions arrive from whatever wrote them — a person, a template, another model — and phrasing, length and specificity change the score as much as the image does. The pipeline validates type, size and caption shape only; it cannot detect a non-photographic image, a machine-generated caption, or a caption set that fits nothing. The synthetic tutorial scenes (flat Pillow shapes, no texture, no lighting) are themselves a rendering instrument unlike any COCO photograph, which is why the smoke run's weak fruit diagonal is recorded rather than tuned away.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0`, `torchvision==0.29.0`, `torchaudio==2.11.0`, `transformers==4.57.6`, `safetensors==0.8.0` (installed as a pin; unused by this checkpoint), `numpy==2.5.3`, `pillow==11.3.0`, float32 on CPU; CUDA is used automatically when visible (float32) but was not exercised for this card. Measured on the reference machine with the GPU hidden (`CUDA_VISIBLE_DEVICES=-1`) and the Hub offline (`HF_HUB_OFFLINE=1`): `verify_snapshot` on the 8-file, 895 MB snapshot 0.44 s; load 3.87 s with exactly two `torch.load(weights_only=True)` calls observed; the 3×3 grid (nine pairs, each an ITM and an ITC pass) 3.06 s; one pair on a 4096×4096 blank image 0.60 s — cost is two forward passes per pair, roughly independent of the input resolution after the resize, so a grid scales as images × captions. Data environment: the model assumes everyday photographs and COCO-style English captions; the synthetic tutorial scenes violate the first assumption on purpose (flat cartoons), which is where the weak fruit diagonal comes from. Documents, non-English captions, attribute-level distinctions and caption sets that fit nothing violate it to degrees this repository did not measure, and the pipeline reports no signal when they do.

#### Metrics

###### Performance Measures

The pipeline reports no accuracy measure. The ITM probability is an uncalibrated per-pair classifier output, the cosine is a similarity, and neither is a correctness signal. The repository ships the retrieval field's simplest building block because it is what a caller would use to evaluate: `recall_at_1(scores, correct)` — the fraction of rows whose highest-scoring column is the labelled one — applied to both grids in both directions by the public `evaluation_report(result, correct_text_per_image=None)` stage, which returns image-to-text and text-to-image `recall_at_1` for the ITM probability and the cosine (the text-to-image direction only for a square one-to-one grid), the chance baselines (1/captions and 1/images) and the verdict `sample-sanity`, or the verdict `not-measurable` naming the labelled set that would be required when no correspondence is supplied. Retrieval is conventionally reported as recall@1/5/10 and median rank over thousands of candidates (COCO 5k, Flickr30k 1k), which this package's 16×16 grid cannot express; a deployment that needs those numbers must build its own candidate index and evaluation. The upstream paper's COCO retrieval recall@1 for its ViT-B models (upstream-reported; not restated here because the hosted card gives no number) is not reproduced or claimed by this pipeline.

###### Decision thresholds

No score threshold exists in the model: it scores every pair and the ranking picks the highest, nothing is filtered or abstained, and this package ships no cut-off on the ITM probability or the cosine — the smoke run's own captions scored 0.998, 0.634 and 0.278, so any fixed threshold would have accepted one drawn scene and rejected another. The decision parameter is the **caption set** (and the image set): which candidates are offered, how they are phrased, and whether the true match is among them — the same house scored `a red house` 0.64, `a house` 0.30, `a green tree` 0.02 and `a blue house` 0.005, so phrasing is part of the request. `format_texts` applies one fixed normalisation (whitespace collapsed; case preserved for the cased-insensitive BERT tokenizer to lower) so the same caption always produces the same score. A deployment owns its candidate sets and any threshold it applies, and decides how a match is verified before it is used.

###### Approaches to uncertainty and variability

This repository reports no central metric value and therefore no dispersion: the smoke run records timings and the nine pair scores of one drawn grid, not retrieval quality. Run-to-run variability comes only from floating-point kernel selection across CPU builds and accelerators; there is no sampling and no seed to set, so a fixed input on fixed hardware is repeatable, but CPU and CUDA scores can differ in the low decimals and a close pair can swap ranks; the drawn scenes use no text rendering, so their bytes do not depend on the Pillow build. On the drawn 3×3 grid every image's own caption ranked first by both scores — ITM 0.998 (house), 0.634 (beach), 0.278 (fruit) with off-diagonal ITM ≤ 0.001, and cosine 0.495 / 0.422 / 0.441 on the diagonal against 0.199–0.292 off it — `recall_at_1` 1.0 in both directions by both scores, one observation on nine drawn pairs, not an estimate; a blank white image scored ITM 0.04–0.07 and cosine 0.29–0.33 against all three captions, and uniform noise ITM 0.001 and cosine 0.12–0.21, which is what a scorer with no abstention looks like — every pair receives a number and every image a best caption. A caller who needs a retrieval estimate must supply captioned images and compute recall@k over many candidates or bootstrap resamples themselves; a caller who needs a calibrated match probability has none from this model.

#### Ethical considerations and biases

No external ethics board, red-team, or population-specific clearance reviewed this repository or, to our knowledge, the upstream checkpoint; nothing below should be read as implying one.

###### Data

The upstream paper describes pretraining on 129M image–text pairs from COCO, Visual Genome, Conceptual Captions 3M and 12M, SBU Captions and a 115M-image LAION subset — web-scraped pairs whose images and captions can include real, identifiable people, copyrighted photographs and stereotyped or offensive text, filtered only by BLIP's own learned filter — and fine-tuning on COCO Captions, whose images are Flickr photographs of people and everyday scenes with crowd-written descriptions; personal data in the training corpora is therefore present by construction. Neither was audited here. This repository distributes code, tests, and documentation; it does not distribute the 895,139,697-byte `pytorch_model.bin` (staged locally under `weights/blip-itm-base-coco/` and git-ignored) nor the 895,599,664-byte `tf_model.h5` (never fetched by this package), and it ships no sample photographs — the tutorial scenes are drawn in code. The operator must audit the images and captions they submit for personal, proprietary, or otherwise restricted content; the pipeline performs no such check and will score a caption about a person's appearance as readily as one about a house.

###### Human Life

This pipeline is not intended for decisions in health, safety, criminal justice, employment, credit, or housing, and it has not been validated or certified for any of them by this repository, the upstream authors, or any regulator. Foreseeable but unintended sensitive uses — accepting or rejecting alt-text for blind or low-vision users on the strength of a match score, deciding that an image "matches" a description of a person for identification or verification, moderation or authenticity judgements, screening user-submitted image–text pairs — would be admissible only with human review of every pair (the model scores any pair and gives no signal when the caption set fits nothing), a locally measured recall@k on the deployment's own captioned images stratified by depicted group, a documented candidate-set and threshold policy, an explicit list of captions about people that are refused before they reach the model, and whatever regulatory clearance the domain requires.

###### Mitigations

- **Supply-chain integrity:** `MODEL_REVISION` is a 40-hex commit; `stage_missing_files` refuses a manifest whose `modelId`/`revision` differ from the package constants and fetches only manifest-listed files at that revision when `allow_download=True`; `verify_snapshot` then checks all 8 listed files' byte sizes and SHA-256 before any load — **including the pickle checkpoint, so a modified `pytorch_model.bin` never reaches a deserialiser**; `from_pretrained` loads only from the verified directory with `local_files_only=True`, always passes `trust_remote_code=False`, `use_safetensors=False` (naming the format) and `weights_only=True` (restricted unpickler: tensors, primitives and containers only), and the smoke run loaded and scored with `HF_HUB_OFFLINE=1` while observing exactly two `torch.load(weights_only=True)` calls. The upstream `tf_model.h5` is neither listed nor loaded. A test flips one hex digit of a manifest digest and asserts the loader refuses; another asserts a foreign manifest is refused; the import-boundary tests assert that a missing or tampered snapshot is refused before `torch` or `transformers` is imported; another asserts the manifest lists the pickle and not the TensorFlow file.
- **Input integrity:** the public `validate_inputs(images, texts)` stage applies exactly the checks `score` applies (both route through one shared private checker) and returns an input manifest recording the schema, the ceilings, each input's observed mode and size, the checked captions, the pair count and the verdict; non-PIL inputs, sides outside 16–4096 px, too many images, and non-list, empty, non-string, over-long, duplicate or too many captions are rejected; `score` raises on a malformed runner result (missing keys, wrong ITM logit shape, non-finite values); `evaluation_report` rejects mismatched or invalid correspondences; `recall_at_1` rejects non-grid inputs.
- **Reproducibility:** exact `==` pins in `pyproject.toml`; deterministic forward passes and softmax; fixed caption normalisation; every result carries `model_id`, `model_revision`, the checked captions, the image sizes, the device and the dtype.
- **Refusals:** no corpus index, no batching beyond the grid, no download without the explicit flag, no Hub access at inference time, no unrestricted pickle deserialisation, no threshold invented, and no filtering of caption content — that policy is the operator's to implement around the pipeline.
- No statistical mitigation (class balancing, subsampling) applies: no training happens in this repository.

###### Risks and harms

- **A best caption for anything:** the model has no abstention — a blank image and uniform noise both received rankings in the smoke run — so a caption set with nothing that fits still crowns a caption, and a consumer that trusts `rankings[0]` (alt-text pickers, deduplication, moderation) inherits the error silently.
- **Uncalibrated match probabilities:** 0.278 was the correct match for the fruit scene and 0.634 for the beach; a fixed threshold accepts and rejects arbitrarily across images, and a high probability is not evidence of a correct description.
- **Phrasing dependence:** the score follows the caption's wording (`a red house` 0.64 vs `a house` 0.30 for the same image); a deployment that authors candidates carelessly authors the ranking.
- **Scoring people by description:** captions naming appearance, dress, ethnicity or disability are scored against images of people with the documented biases of vision–language models; such use can cause direct harm and is prohibited below.
- **Automation bias:** a probability that reads like a confidence invites trust that a per-pair classifier has not earned.
- **Pickle checkpoint:** the executed weight file is a pickle; the digest check and `weights_only=True` are the mitigation, and a caller who bypasses `from_pretrained` and loads the file another way forfeits both.
- **Bias amplification:** any image population or caption style COCO under-represents (non-Western scenes, non-photographic images, minority groups, non-native phrasing) is reproduced as uneven match quality, undetected because no per-group evaluation exists.
- **Resource use:** an 895 MB model and ~0.35 s per pair on the reference CPU; a 16×16 grid is 256 pairs, and the CUDA path was not measured.

###### Use cases

Prohibited even where the model would work: scoring images of people against captions that name or infer protected characteristics (race, ethnicity, religion, health, disability, sexual orientation), or to identify, verify, track, profile or surveil individuals; processing images or captions the operator has no right to process, including intimate imagery and licence-restricted material; presenting match scores as verified descriptions, authenticity judgements or evidence without human review; and any use that violates the upstream BSD-3-Clause licence terms (including use of the Salesforce name for endorsement), the DIMER deployment terms, or the consent and data-protection obligations attached to the images and captions processed. Autonomous high-consequence actions triggered by unreviewed match scores are prohibited by the intended-use contract above.

## Input/output contract

- `BlipItmPipeline.from_pretrained(device=None, weights_dir=None, allow_download=False)` — stages missing manifest files (only with `allow_download=True`), verifies digests, loads; `device` defaults to `cuda:0` when visible, else `cpu`; float32 on both.
- `score(images, texts) -> dict` with keys `itm_probability`, `itm_logit_match`, `cosine` (float64 grids indexed `[image][text]`), `rankings` (per image: `text`, `itm_probability`, `cosine`, descending by ITM probability), `texts` (checked), `n_images`, `image_sizes`, `device`, `dtype`, `source`, `model_id`, `model_revision`.
- `format_texts(texts) -> list[str]`; `recall_at_1(scores, correct) -> float`.
- Ceilings and constants: `MIN_IMAGE_SIDE = 16`, `MAX_IMAGE_SIDE = 4096`, `MAX_IMAGES = 16`, `MAX_TEXTS = 16`, `MAX_TEXT_CHARS = 256`, `IMAGE_SIZE = 384`, `WEIGHT_FILE = "pytorch_model.bin"`, `HOSTED_TF_WEIGHT_FILE = "tf_model.h5"`, `INPUT_SCHEMA`.
- `validate_inputs(images, texts, *, names) -> dict`; `evaluation_report(result, correct_text_per_image=None, *, sample_kind) -> dict` where `correct_text_per_image` holds the matching caption index per image; `verify_snapshot(path=None) -> dict`; `stage_missing_files(path=None, *, allow_download=False, downloader=None) -> list[str]`.
